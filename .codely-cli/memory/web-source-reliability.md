# 联网来源可靠性实测（本机 + 本仓）

用途：跑「游戏 AI 日报」这类定时检索任务时，先按此表选路线，避免每次重复试错。结论来自 2026-11-17 ~ 2026-11-19 三次连续实测，服务器出口 IP 为动态（曾落在 16.208.77.237），限流与 502 可能随环境变化。

## 可用（直接抓，返回正文）

| 来源 | 用法 | 注意 |
|---|---|---|
| `aliyun.com/product/tongyi`、`aliyun.com/product/bailian`、`aliyun.com/benefit/scene/wan` | 官方产品页，能拿到"重磅发布"横幅、适用场景与分档单价（Wan3.0 按秒计费：480P ¥0.45 / 720P ¥0.9 / 1080P ¥1.8） | 产品页口径常与百炼文档不一致（正式版 vs 预览版），需交叉核对 |
| `cloud.tencent.com/document/product/1804/120694` | 混元生 3D 产品动态（表格带日期） | 2026-11 实测停在 2026-01-16，产品线本身可能停更 |
| `klingai.com/document-api/updates/api` | 可灵 API 更新公告（带日期） | 覆盖到 2026-11-04 |
| `aigamehot.com` | AI 游戏资讯聚合，条目带精确到分钟的时间戳 + 来源标注（一手/社区/媒体） | **仅作发现线索**：多数条目原始出处是境外社交平台个人帖；正文为二手改写，个别数字（如"50 小时 / 95% 无人接管"）在论文里查不到对应表述 |
| `news.pynoai.com/topics/model-releases` | 模型发布动态 | 抓取会丢日期表头，条目与日期容易错位 |
| `arxiv.org/abs/<id>`、`mihoyo-gamer.github.io` 等项目页 | 论文摘要与项目信息 | `arxiv.org/list/cs.GR/new` 抓取只返回首条或少量条目，且按美东公告时点落入北京时间次日 09:00 附近，边界很紧 |
| `ziva.sh/blogs/...` | 厂商技术博客，含完整实验表（耗时/成本/上下文） | 典型厂商自测，读时必须标注偏差 |
| `inworld.ai/blog` | 官方博客，含开源许可与自评指标 | 页面**不标发布日期**，需外部核对 |

## 不可用（抓取返回空 / 502 / 限流）

| 来源 | 现象 |
|---|---|
| `aliyun.com/notice`（官网公告） | 脚本渲染，返回"暂未搜索到任何内容" |
| `developer.unity.cn`、`unity.cn` 博客 | 脚本渲染，返回空正文 → Perf Assistant 这类公告无法定位原文 |
| `gamelook.com.cn` | HTTP 502 |
| `api.github.com/repos/...` | `403 API rate limit exceeded`（未认证）；改用网页页面的 web_fetch 可绕开 |
| `next.ithome.com/ai`、`qbitai.com` 首页 | 能抓，但列表排序混乱（会把 10 月/2025 年的条目混在顶部），按日期筛选不可靠 |

## 检索经验

- 搜索引擎对「某个精确日期 + 事件」的召回很差，`"11月17日" + 关键词` 这类查询大量返回历史综述站与时间线长文，不能当日期证据。
- 判断「窗口内有没有新东西」应优先查**官方 changelog / 产品动态页 / arXiv abs**，而不是靠关键词搜索命中。
- 聚合站时间戳可用于初筛，但必须回到一手页面复核：论文提交日、仓库创建日、官方公告日三者常不一致（例：论文 11-13、媒体披露 11-17）。
- GitHub 侧信息（创建时间、star）在未认证限流下拿不到；涉及"是否刚开源"的判断要说明未核实。
