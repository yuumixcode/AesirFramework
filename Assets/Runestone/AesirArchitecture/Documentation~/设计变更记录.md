# 设计变更记录

> 本文档按设计点收录**已废弃的机制**与**设计来源**，帮助理解框架边界的来龙去脉。
> 按版本的完整变更时间线见 [CHANGELOG.md](../CHANGELOG.md)；当前版本的设计边界与编写约定见包 README「设计边界」节。
> 源码注释只描述当前行为，历史演进统一收录于此。

## 一、已废弃的设计点

### 1. Context 事件总线体系

- **曾几何时**：`IContext` / `AbstractContext<T>` 直接提供 `AddListener<T>` / `RemoveListener<T>` / `InvokeEvent<T>` 方法，角色接口含 `ICanAddListener` / `ICanInvokeEvent` 能力，配套 `MiniEventBus.Global` 全局总线与 `ContextBoard` / `MiniEventBusBoard` Inspector 看板（0.2.0 引入）。
- **废弃理由**：内置在 Context 上的事件总线不如独立事件机制实用——订阅入口挂在获取路径上徒增认知负担，跨模块通信有更直接的手段。
- **现行替代**：`MiniEvent` / `MiniEvent<T>`（独立轻量事件）与 `ObservableValue<T>`（响应式属性订阅）；跨模块通信使用互相 GetModel + ObservableValue 订阅。
- **时间线**：总线本体于 0.3.2 后移除；`IController` 于 0.3.1 率先移除 `ICanAddListener`；角色接口与 `IContext` 事件方法于 2026-07-30 彻底清除；0.9.0 修正 package.json 描述文案。

### 2. ModelReplaced / ServiceReplaced 替换通知事件

- **曾几何时**：动态替换 Model / Service 时框架发出替换通知事件，供订阅方迁移。
- **废弃理由**（0.9.0 删除）：运行时替换属测试/调试用途，不应为低频路径徒增框架事件面。
- **现行替代**：动态替换仍会 Dispose 旧实例并输出 Warning 日志提醒「订阅不会迁移」；测试环节自行处理订阅迁移。

### 3. PlayerLoop 120 帧自愈轮询

- **曾几何时**：`MonoLifecycleProxy` 每 120 帧检测一次 PlayerLoop 注入是否被第三方 SDK 覆盖，被覆盖则自动补插。
- **废弃理由**（0.9.0 移除）：时好时坏的自愈有隐性代价（隐藏根因、周期性空转），低概率问题应靠文档约定在项目前期杜绝。
- **现行替代**：`AesirArchitecturePlayerLoop.EnsureInjected()` 幂等公开 API（域加载时 + 每次 `Register` 时自动检测补插）；已知第三方修改 PlayerLoop 后手动调用一次即可。

### 4. 初始化失败回滚 Dispose

- **曾几何时**：`AbstractContext<T>.Initialize` 失败时快照跟踪已初始化模块并按逆序回滚 Dispose。
- **废弃理由**（0.9.0 撤销）：初始化失败属启动期编程错误，应修复根因而非优雅降级；回滚掩盖真实故障点。
- **现行替代**：初始化**成功后**才写入静态单例字段 `_instance`；失败不缓存、根因异常每次访问重新抛出，半成品模块随被丢弃的实例交由 GC 回收。

### 5. 监听回调异常吞噬

- **曾几何时**：`MiniEvent.Invoke` / `MonoLifecycleProxy.InvokeEvent` / `AesirArchitecturePlayerLoop.InvokeHooks` 对每个回调逐个 try-catch，防止单个监听者异常中断其他监听者。
- **废弃理由**（0.9.0 撤销）：吞噬异常掩盖根因；逐回调 try-catch 破坏零分配直调的核心卖点。
- **现行替代**：fail-fast——异常直接向上传播并中断同事件后续回调（原生 C# 事件语义），由 Unity 记日志；「监听回调不应抛异常」为框架编写约定。`AesirArchitecturePlayerLoop` 遍历中的 `finally` 仅保证调用状态机复位与延迟命令执行，不吞异常。

### 6. BeforeFixedUpdate 生命周期事件

- **曾几何时**：`MonoLifecycleEvent` / `AesirArchitectureLifecyclePhase` 含 `BeforeFixedUpdate` 枚举值，经 PlayerLoop 注入触发。
- **废弃理由**（0.8.0 移除）：注入点经 PlayerLoop **每帧**触发，但 `FixedUpdate` 并非每帧执行——事件名暗示的触发频率与实际不符，语义误导且无实际使用。
- **现行替代**：不提供；需要「物理帧之前」逻辑直接写在 MonoBehaviour 的 `FixedUpdate` 回调中。`MonoLifecycleProxy` 的排序机制（Order + InsertionIndex 稳定排序）同期修复。

### 7. GenericLocator 全局定位器与注册表暴露

- **曾几何时**：`GenericLocator<T>.Global` 全局单例定位器（`AbstractContext` 曾注册到 `GenericLocator<IContext>.Global`），以及 `GetRegistry()` 方法暴露底层字典。
- **废弃理由**：`Global` 鼓励绕过 Context 直接全局取件，破坏模块边界；`GetRegistry()` 是泄漏底层字典引用的封装漏洞（0.9.0 删除，全仓库无调用方）。
- **现行替代**：`GenericLocator<T>` 仅作 Context 内部容器组合使用；框架外部经 `GetModel` / `GetService` 访问。

### 8. AbstractContext 属性名 Interface 与返回类型 IContext

- **曾几何时**：单例访问属性名为 `AbstractContext<T>.Interface`，返回 `IContext` 接口。
- **变更理由**（0.10.0 更名）：与 C# 关键字 `interface` 术语混淆；返回接口使 Context 子类访问自定义成员需要强转。
- **现行替代**：`Instance` 属性返回具体类型 `T`，访问 `IContext` 接口成员时自动向上转型。

### 9. 无条件 DDOL 与来源标志组合

- **曾几何时**：MonoBehaviour 单例无条件 `DontDestroyOnLoad`，后以 `_createdByRuntime` / `_pendingDontDestroyOnLoad` / `_isPrePlaced` 等静态/实例标志组合区分「预放置实例保留场景、运行时创建实例 DDOL」。
- **变更理由**（0.11.0 重设计）：标志组合复杂且语义分裂——两种实例来源应有同一份持久化决策。
- **现行替代**：`[SerializeField] bool dontDestroyOnLoad = true` 序列化字段统一决策；关闭时实例随场景卸载销毁（Inspector 警告 + 运行时提醒日志），多场景叠加（Additive）生命周期由使用者管理。

### 10. 依赖 Unity fake-null 的隐式静态重置

- **曾几何时**：`AesirArchitecture` 的静态 `_instance` 不做显式重置，依赖「退出 Play 时对象销毁、Unity fake-null 使 `_instance != null` 自然变 false」隐式救援。
- **变更理由**（0.10.0 补显式重置）：隐式机制属「碰巧正确」而非「按原则正确」，是框架静态重置铁律的唯一例外。
- **现行替代**：非泛型单例一律类内声明 `[RuntimeInitializeOnLoadMethod(SubsystemRegistration)]` 显式重置；泛型类（RIOLM 被 Unity 静默跳过）经 `ResetStaticsAssistant` 注册重置回调。

## 二、设计来源

框架按实用性裁剪，不强求原创；下列项目在机制或链路上被参考，特此致谢。

| 来源 | 借鉴点 | 本框架的处理 |
|------|--------|--------------|
| [QFramework](https://github.com/liangxiegame/QFramework)（MIT） | 包内更新器的更新链路（PackageKit：版本记录随包走 + 先删后导） | `AesirUpdateService` / `AesirUpdateWindow` 在此基础上增强：更新前自动备份、按「上次安装清单 − 新版清单」精确差集清理残留。许可声明见 [Third Party Notices.md](../Third%20Party%20Notices.md) |
| Odin Inspector（Sirenix，商业授权） | `ScriptingSymbolUtility` 的宏管理方式（`EnsureOdinInspectorDefine` 同构的遍历 + 幂等写入） | 框架核心不依赖 Odin，经 `#if ODIN_INSPECTOR` 条件编译可选集成，未安装时相关代码整体编译剔除 |
| Aesir Inspector（同作者独立包） | `QuickCreateSOMenuItem` 与其同名工具同源 | 两包共存时经 `AESIR_INSPECTOR` 宏让位：检测到该宏时本包版本整体不编译，避免重复菜单项 |
| [Cysharp.ObservableCollections](https://github.com/Cysharp/ObservableCollections)（MIT） | 可观察集合家族的能力边界参照 | 本框架仅提供最常用的增删改查事件；Move、Sort、同步视图、R3 集成等高级能力不做，需要时推荐直接使用该方案 |

## 三、命名演进速查

早期版本的命名与现名差异较大，迁移旧代码时可对照：

| 旧名（≤ 0.3.x） | 现名 |
|------------------|------|
| `Subscribe` / `Unsubscribe` | `AddListener` / `RemoveListener`（对齐 Unity `UnityEvent` 命名） |
| `AutoUnsubscribeHandle` | `AutoRemoveListenerHandle` |
| `UnsubscribeOnDestroyInvoker` 等 | `RemoveListenerOnDestroyTrigger` 等 |
| `ContextResetAssistant` → `GenericResetStaticsAssistant` | `ResetStaticsAssistant` |
| `OdinIntegration`（程序集/目录） | `OdinInspector` |
| `AesirArchitectureLifeCyclePhase` | `AesirArchitectureLifecyclePhase`（Lifecycle 单词拼写统一） |
