# 常见陷阱清单

> 每条配错误现象 + 原因 + 一句话修法。异常消息截图以实际报错为准（框架的 fail-fast 消息已含修复指引）。

## 1. 按实现类注册、按接口获取（Register/Get 类型参数不一致）

- **现象**：`GetModel<T>()` 抛 `InvalidOperationException`：「该 Model 未在 Context 中注册」
- **原因**：`RegisterModel<CounterModel>(...)` 按实现类注册，却 `GetModel<ICounterModel>()` 按接口查询——键精确匹配失败
- **修法**：Register 与 Get 使用**相同类型参数**（推荐都用接口）。0.10.0 起异常消息含近失识别提示（「检测到已注册实例可赋值给查询类型——Register 与 Get 必须使用相同类型参数」）

## 2. 在 Configure() 或模块 OnInitialize() 中访问 Instance

- **现象**：`NullReferenceException` 或行为异常（拿到了第二个 Context 实例）
- **原因**：`Instance` getter 懒加载，Configure 执行期间单例尚未发布，访问会递归创建第二个上下文
- **修法**：Configure 中只做 `RegisterModel/RegisterService`；模块间互相访问放到 `OnInitialize()`（此时全部已注册完毕）

## 3. 注册顺序错误 / 模块循环依赖

- **现象**：`GetModel<T>()` 抛「该 Model 尚未初始化。这通常表示注册顺序错误或存在循环依赖」
- **原因**：被依赖的模块还没注册完，依赖方就先初始化了
- **修法**：Configure 中**被依赖的模块先注册**（框架按注册顺序初始化 Model → Service）

## 4. 监听回调里抛异常

- **现象**：一个监听者抛异常后，同事件的后续监听者全部不执行
- **原因**：`MiniEvent` 是零分配直调，异常语义 = 原生 C# 事件（fail-fast）
- **修法**：**监听回调不应抛异常**（框架约定）；业务异常在回调内部自行 try-catch 处理

## 5. 忘记绑定自动注销句柄

- **现象**：GameObject 销毁后仍收到事件通知 / 内存泄漏
- **原因**：`AddListener` 返回的 `AutoRemoveListenerHandle` 未绑定生命周期
- **修法**：`.AddListener(cb).RemoveListenerWhenGameObjectOnDestroyed(gameObject)` 一行绑定；UI 面板等频繁启停对象用 `RemoveListenerWhenGameObjectOnDisable`

## 6. OnDisable 中用 RemoveAllListeners()

- **现象**：自己的监听被清掉了，但**别的系统**挂在同一按钮上的监听也莫名失效
- **原因**：`RemoveAllListeners` 一刀切清空所有监听者（包括其他框架/插件挂的）
- **修法**：与 `OnEnable` **逐一对称**的 `RemoveListener(...)`：`OnEnable` 加什么，`OnDisable` 就精确移除什么

## 7. 在 Update 等每帧路径调用 GetModel<T>()

- **现象**：帧率下降、GC 分配
- **原因**：`GetModel` 每次访问 = 字典查找 + 初始化检查
- **修法**：在 `Awake`/`OnInitialize` 缓存字段引用 `_model = this.GetModel<T>()`；属性 getter 形式（`Model => this.GetModel<T>()`）**不推荐用于每帧路径**——如确需每帧调用，请自行确认必要性

## 8. 把核心配置只放在 Inspector 面板上

- **现象**：配置改动无法 diff、无法搜索，AI 辅助开发时 AI 无法读取/修改配置
- **原因**：面板点击操作对 AI 难驱动、易出错
- **修法**：核心配置首选代码与资产文件（ScriptableObject 资产、代码常量）；Inspector 面板是**调试加成**，非必要不把配置只放面板

## 9. 用 Action 属性代替 event

- **现象**：外部代码把事件链整体替换（`view.XxxClicked = null`）或直接触发（`view.XxxClicked()`）
- **原因**：`public Action Xxx { get; set; }` 的 public setter 把委托链管理权开放给了所有引用持有者
- **修法**：接口中声明 `event Action Xxx;`——编译期限制外部只能 `+=`/`-=`

## 10. 运行时替换 Model 后期望旧订阅自动迁移

- **现象**：`RegisterModel` 替换实例后，View 收不到新实例的通知
- **原因**：替换时旧实例被 Dispose，其上的订阅**不会迁移**到新实例
- **修法**：运行时替换仅用于测试/调试；已订阅的 View 需自行重新订阅（示例中的 `Model => this.GetModel<T>()` 属性形式保证始终拿到最新实例）
