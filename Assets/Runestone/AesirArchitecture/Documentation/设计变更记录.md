# 设计变更记录

> 本文档按设计点收录**已废弃的机制**与**设计来源**，帮助理解框架边界的来龙去脉。
> 按版本的完整变更时间线见 [CHANGELOG.md](../CHANGELOG.md)；当前版本的设计边界与编写约定见包 README「设计边界」节。
> 源码注释只描述当前行为，历史演进统一收录于此。

## 一、已废弃的设计点

### 1. Context 事件总线体系

- **曾几何时**：`IContext` / `AbstractContext<T>` 直接提供 `AddListener<T>` / `RemoveListener<T>` / `InvokeEvent<T>` 方法，角色接口含 `ICanAddListener` / `ICanInvokeEvent` 能力，配套 `MiniEventBus.Global` 全局总线与 `ContextBoard` / `MiniEventBusBoard` Inspector 看板（0.2.0 引入）。
- **废弃理由**：内置在 Context 上的事件总线不如独立事件机制实用——订阅入口挂在获取路径上徒增认知负担，跨模块通信有更直接的手段。
- **现行替代**：`MiniEvent` / `MiniEvent<T>`（独立轻量事件）与 `ObservableValue<T>`（响应式属性订阅）；跨模块通信使用互相 GetModel + ObservableValue 订阅。
- **时间线**：总线本体于 0.3.2 后移除；`IController` 于 0.3.1 率先移除 `ICanAddListener`；角色接口与 `IContext` 事件方法于 2026-07-30 彻底清除；0.9.0 修正 package.json 描述文案。

### 2. ModelReplaced / ServiceReplaced 替换通知事件

- **曾几何时**：动态替换 Model / Service 时框架发出替换通知事件，供订阅方迁移。
- **废弃理由**（0.9.0 删除）：运行时替换属测试/调试用途，不应为低频路径徒增框架事件面。
- **现行替代**：动态替换仍会 Dispose 旧实例并输出 Warning 日志提醒「订阅不会迁移」；测试环节自行处理订阅迁移。

### 3. PlayerLoop 120 帧自愈轮询

- **曾几何时**：`MonoLifecycleProxy` 每 120 帧检测一次 PlayerLoop 注入是否被第三方 SDK 覆盖，被覆盖则自动补插。
- **废弃理由**（0.9.0 移除）：时好时坏的自愈有隐性代价（隐藏根因、周期性空转），低概率问题应靠文档约定在项目前期杜绝。
- **现行替代**：`AesirPlayerLoop.EnsureInjected()` 幂等公开 API（域加载时 + 每次 `Register` 时自动检测补插）；已知第三方修改 PlayerLoop 后手动调用一次即可。

### 4. 初始化失败回滚 Dispose

- **曾几何时**：`AbstractContext<T>.Initialize` 失败时快照跟踪已初始化模块并按逆序回滚 Dispose。
- **废弃理由**（0.9.0 撤销）：初始化失败属启动期编程错误，应修复根因而非优雅降级；回滚掩盖真实故障点。
- **现行替代**：初始化**成功后**才写入静态单例字段 `_instance`；失败不缓存、根因异常每次访问重新抛出，半成品模块随被丢弃的实例交由 GC 回收。

### 5. 监听回调异常吞噬

- **曾几何时**：`MiniEvent.Invoke` / `MonoLifecycleProxy.InvokeEvent` / `AesirPlayerLoop.InvokeHooks` 对每个回调逐个 try-catch，防止单个监听者异常中断其他监听者。
- **废弃理由**（0.9.0 撤销）：吞噬异常掩盖根因；逐回调 try-catch 破坏零分配直调的核心卖点。
- **现行替代**：fail-fast——异常直接向上传播并中断同事件后续回调（原生 C# 事件语义），由 Unity 记日志；「监听回调不应抛异常」为框架编写约定。`AesirPlayerLoop` 遍历中的 `finally` 仅保证调用状态机复位与延迟命令执行，不吞异常。

### 6. BeforeFixedUpdate 生命周期事件

- **曾几何时**：`MonoLifecycleEvent` / `AesirLifecyclePhase` 含 `BeforeFixedUpdate` 枚举值，经 PlayerLoop 注入触发。
- **废弃理由**（0.8.0 移除）：注入点经 PlayerLoop **每帧**触发，但 `FixedUpdate` 并非每帧执行——事件名暗示的触发频率与实际不符，语义误导且无实际使用。
- **现行替代**：不提供；需要「物理帧之前」逻辑直接写在 MonoBehaviour 的 `FixedUpdate` 回调中。`MonoLifecycleProxy` 的排序机制（Order + InsertionIndex 稳定排序）同期修复。

### 7. GenericLocator 全局定位器与注册表暴露

- **曾几何时**：`GenericLocator<T>.Global` 全局单例定位器（`AbstractContext` 曾注册到 `GenericLocator<IContext>.Global`），以及 `GetRegistry()` 方法暴露底层字典。
- **废弃理由**：`Global` 鼓励绕过 Context 直接全局取件，破坏模块边界；`GetRegistry()` 是泄漏底层字典引用的封装漏洞（0.9.0 删除，全仓库无调用方）。
- **现行替代**：`GenericLocator<T>` 仅作 Context 内部容器组合使用；框架外部经 `GetModel` / `GetService` 访问。

### 8. AbstractContext 属性名 Interface 与返回类型 IContext

- **曾几何时**：单例访问属性名为 `AbstractContext<T>.Interface`，返回 `IContext` 接口。
- **变更理由**（0.10.0 更名）：与 C# 关键字 `interface` 术语混淆；返回接口使 Context 子类访问自定义成员需要强转。
- **现行替代**：`Instance` 属性返回具体类型 `T`，访问 `IContext` 接口成员时自动向上转型。

### 9. 无条件 DDOL 与来源标志组合

- **曾几何时**：MonoBehaviour 单例无条件 `DontDestroyOnLoad`，后以 `_createdByRuntime` / `_pendingDontDestroyOnLoad` / `_isPrePlaced` 等静态/实例标志组合区分「预放置实例保留场景、运行时创建实例 DDOL」。
- **变更理由**（0.11.0 重设计）：标志组合复杂且语义分裂——两种实例来源应有同一份持久化决策。
- **现行替代**：`[SerializeField] bool dontDestroyOnLoad = true` 序列化字段统一决策；关闭时实例随场景卸载销毁（Inspector 警告信息框提示），多场景叠加（Additive）生命周期由使用者管理。

### 10. 依赖 Unity fake-null 的隐式静态重置

- **曾几何时**：`AesirArchitecture` 的静态 `_instance` 不做显式重置，依赖「退出 Play 时对象销毁、Unity fake-null 使 `_instance != null` 自然变 false」隐式救援。
- **变更理由**（0.10.0 补显式重置）：隐式机制属「碰巧正确」而非「按原则正确」，是框架静态重置铁律的唯一例外。
- **现行替代**：非泛型单例一律类内声明 `[RuntimeInitializeOnLoadMethod(SubsystemRegistration)]` 显式重置；泛型类（RIOLM 被 Unity 静默跳过）经 `ResetStaticsAssistant` 注册重置回调。

### 11. 可观察集合双轨事件体系（0.22.0 收敛单轨）

- **曾几何时**：0.21 全量复刻时代并存两套通知轨道——逐类轻量事件（`AddAddedListener` / `AddRemovedListener` / `AddReplacedListener` / `AddUpdatedListener` / `AddClearedListener` 族 + `CollectionAddEventArgs` 等专用载荷）与上游移植的原生 `CollectionChanged` 事件（`NotifyCollectionChangedEventHandler<T>` + `NotifyCollectionChangedEventArgs<T>`）。
- **变更理由**（0.22.0 单轨收敛）：双轨需记两套语义、每个写操作双分发；原生 event 订阅接不了 `AutoRemoveListenerHandle` 的 Unity 生命周期绑定。
- **现行替代**：单轨 `IObservableCollection<T>.AddListener(Action<CollectionChangedEventArgs<T>>)`（`MiniEvent` 承载，返回 `AutoRemoveListenerHandle` 可绑 GameObject 销毁 / 场景卸载自动注销），载荷为普通只读结构体 `CollectionChangedEventArgs<T>`（Add / Remove / Replace / Move / Reset 静态工厂）。语义要点：无变更不通知、批量操作逐项通知、字典值更新为 Replace（旧值在 OldItem）、Move 单事件、Sort / Reverse / Clear 统一 Reset。

### 12. 更新器更新前自动备份

- **曾几何时**：更新器每次执行更新前把安装根整体复制到项目根 `.aesir-backup/`（时间戳目录、保留最近 3 份），作为导入失败 / 本地修改被覆盖时的还原来源。
- **变更理由**：全量复制数千文件到消费者项目根，对 git 仓库构成无谓的提交噪音与磁盘占用；标准用户的回滚路径本就更优——上一版本 unitypackage 永久保留在 GitHub Releases，重新导入即完整还原（残留清理只动安装清单内的文件、用户新增文件不受影响），且更新本身刚用过网络；「本地修改会被 Release 内容覆盖」属不推荐用法，由确认框明示而非运行时防御。
- **现行替代**：无本地备份。回滚 = 从 GitHub Releases 下载对应版本 unitypackage 重新导入（确认框与导入失败告警均指向该路径）；残留清理在导入成功之后执行，导入失败时旧文件原封不动。

### 13. 可观察队列 `ObservableQueue<T>`（0.22.0 引入，随极简收敛移除）

- **曾几何时**：可观察集合家族内置四种集合（List / Dictionary / HashSet / Queue），`ObservableQueue<T>` 提供 FIFO 队列的单轨变更通知（入队 Add / 出队 Remove、`EnqueueRange` / `DequeueRange` 批量逐项通知）。
- **变更理由**：队列是四集合中使用频率最低的一种（背包 / 配置表 / 状态集合均高频，消息队列场景相对少见），且是四者中唯一没有写侧接口的集合——Model 层只能依赖具体 sealed 类，DIP 断层；为最低频形态补一套接口与测试属概念负担大于收益。
- **现行替代**：内置家族收敛为三种高频集合（List / Dictionary / HashSet）；需要队列（FIFO）时直接使用上游 [Cysharp.ObservableCollections](https://github.com/Cysharp/ObservableCollections)（其 `ObservableQueue<T>` 为完整实现），两套体系命名空间隔离、可同项目共存。


### 14. 帧粒度时间调度器 `AesirScheduler`（0.21.0 引入，随极简收敛移除）

- **曾几何时**：`AesirScheduler` 提供纯 C# 静态 API `Delay(seconds, callback)` / `NextFrame(callback)`，经 PlayerLoop BeforeUpdate 钩子结算，定位是"为无协程能力的 Model / Service / Command 提供合法延时手段"，实现刻意收窄（帧粒度、游戏时间、一次性任务、稳态零分配）。
- **变更理由**：自引入起**全仓零使用**——源码引用仅存在于其自身定义与专属测试，11 个示例、Runtime 全部代码、文档示例无一处调用。框架唯一的完整游戏示例 `PlaneWar` 的敌机刷怪、子弹生命周期、玩家复活、计分 6 个脚本全部走普通 `MonoBehaviour.Update()`，即最该用帧级调度的场景恰恰没用。原始立论"纯 C# 层没有延时手段"已被框架自有的两条路径覆盖：`MonoLifecycleProxy` 让纯 C# 类零场景物体地拿到 `Update` / `FixedUpdate` / `LateUpdate`（DDOL 自动建宿主），一个计时字段即可实现延时；真需要协程语义时把驱动方挂在 GameObject 上是 Unity 原生答案。**同一需求三条路径并存而无人使用，是极简原则下的净负债**——初学者面对三选一反而更难决策。
- **现行替代**：纯 C# 类需要每帧回调 → 实现 `ICustomUpdate` / `ICustomFixedUpdate` / `ICustomLateUpdate` 并用 `MonoLifecycleProxy.Register` 注册；需要协程 / 计时器 → 把驱动方挂在 GameObject 上用 `StartCoroutine`。`AesirPlayerLoop` 本体保留（它是独立的帧钩子原语，不专属调度器）。

## 三、命名演进速查

命名规范（2026-09-29 定案）：**跨包共用**（一个实现、两包都用，或框架级公共工件）→ 直接 `Aesir` + 语义名，**不带** `Architecture` / `Modules` 包名段；**两包各自拥有一份同类角色** → 用**完整包名** `AesirArchitecture` / `AesirModules` + 语义名，使两包角色成对可辨（宿主单例、日志门面即此类）；单包自有且无跨包对照角色 → 维持现状。分界依据是「有没有第二个包的对照实现」，**不是**「当前有没有被第二个包引用」。

早期版本的命名与现名差异较大，迁移旧代码时可对照：

| 旧名（≤ 0.3.x） | 现名 |
|------------------|------|
| `Subscribe` / `Unsubscribe` | `AddListener` / `RemoveListener`（对齐 Unity `UnityEvent` 命名） |
| `AutoUnsubscribeHandle` | `AutoRemoveListenerHandle` |
| `UnsubscribeOnDestroyInvoker` 等 | `RemoveListenerOnDestroyTrigger` 等 |
| `ContextResetAssistant` → `GenericResetStaticsAssistant` | `ResetStaticsAssistant` |
| `OdinIntegration`（程序集/目录） | `OdinInspector` |
| `AesirArchitectureLifeCyclePhase` | `AesirLifecyclePhase`（Lifecycle 单词拼写统一，随后去包名段——见下三行） |
| `AesirArchitecturePlayerLoop` | `AesirPlayerLoop`（跨包共用的框架级帧钩子：按命名规范去包名段；宿主 `AesirArchitecture` 与门面 `AesirArchitectureDebug` 属"两包成对角色"，**保留全名**） |
| `AesirArchitectureLifecyclePhase` | `AesirLifecyclePhase`（与上一行同批执行，避免 `AesirPlayerLoop.Register(AesirArchitectureLifecyclePhase, …)` 只改一半） |
| `AesirArchitectureScriptRunBeforeUpdate` / `…AfterUpdate` | `AesirScriptRunBeforeUpdate` / `AesirScriptRunAfterUpdate`（PlayerLoop 子系统私有类型标识，随宿主类同名精简） |
