# save-module — Delta Spec

## Purpose

为 RAM 提供面向独立游戏的保存模块行为契约：以存档槽键值语义保存与加载纯数据对象，保证写入的崩溃安全（任意中断点至少一份完整可读存档）、损坏检测与备份回退，并以可替换的序列化 / 存储 / 保存管理扩展点支持自定义保存方案。

## ADDED Requirements

### Requirement: 存档保存与加载往返

模块 SHALL 提供以字符串键标识的存档槽：`SaveModule.Save<T>(key, data)` 将数据对象持久化，`SaveModule.Load<T>(key)` 读回同类型数据；同键重复保存 SHALL 覆盖旧值，加载返回最近一次成功保存的数据。保存与加载 SHALL 返回结果对象表达成败，而非以异常表达可预期的环境失败。

#### Scenario: 保存后加载往返一致

- **WHEN** 调用 `Save("slot0", data)` 成功后调用 `Load<T>("slot0")`
- **THEN** 结果状态为成功，返回的数据与保存时逐字段相等

#### Scenario: 同键覆盖

- **WHEN** 对同一键先后保存两份不同数据后加载
- **THEN** 返回后一份数据

#### Scenario: 加载不存在的键

- **WHEN** 对从未保存过的键调用 `Load<T>`
- **THEN** 结果状态为 `NoSave`，不抛异常，值为类型默认值

#### Scenario: 删除存档

- **WHEN** 对已存在的键调用 `Delete(key)` 后加载
- **THEN** 删除成功且后续加载返回 `NoSave`；删除不存在的键无副作用

### Requirement: 存档键合法性

存档键 MUST 仅由字母、数字、下划线与连字符组成且非空；含路径分隔符、`..`、空白或其他字符的键 MUST 被拒绝（抛 `ArgumentException`），以防止路径穿越写到存储目录之外。

#### Scenario: 合法键接受

- **WHEN** 使用 `"slot_0"`、`"Quicksave-1"` 等键保存
- **THEN** 保存正常执行

#### Scenario: 非法键拒绝

- **WHEN** 使用 `""`、`"../escape"`、`"a/b"`、`"a b"` 等键调用保存或加载
- **THEN** 抛 `ArgumentException`，存储目录之外不产生任何文件

### Requirement: 事务式写入的崩溃安全

保存 MUST 以事务式流程落盘：新数据先写入同目录临时文件并强制刷盘，再经备份轮换与原子替换提交；写入流程的任意中断点（进程崩溃 / 断电）之后，磁盘上 MUST 至少保留一份完整可读的存档（旧值或新值），不得出现主存档被截断且无备份的状态。残留的临时文件 MUST NOT 影响后续加载与保存。

#### Scenario: 临时文件残留不影响加载

- **WHEN** 存储目录中存在上次中断遗留的 `.tmp` 文件时执行加载
- **THEN** 加载读取已提交的主存档，忽略临时文件

#### Scenario: 提交前中断后仍可读取旧档

- **WHEN** 模拟写入中断（主存档已被轮转为备份、临时文件未提交）后执行加载
- **THEN** 加载从备份恢复出完整旧数据，结果标明来源为备份

#### Scenario: 再次保存清理残留

- **WHEN** 存在残留临时文件时执行一次新的保存
- **THEN** 保存成功，临时文件被复用或覆盖，不累积垃圾文件

### Requirement: 完整性校验与损坏回退

每份存档 MUST 携带完整性校验信息；加载时校验失败（内容被截断、篡改或位翻转）MUST 判定该份存档损坏。主存档损坏而备份完好时，加载 MUST 自动回退到备份并在结果中标明来源；主存档与备份均损坏（或均缺失有效数据）时，加载 MUST 返回 `Corrupted` 状态与错误描述，不返回部分数据、不抛异常。加载路径 MUST 无磁盘写副作用（只读回退，不改写文件）。

#### Scenario: 主存档损坏回退备份

- **WHEN** 主存档字节被破坏、备份完好时调用加载
- **THEN** 结果为成功，值等于上一次提交的数据，来源标明为备份

#### Scenario: 主备均损坏

- **WHEN** 主存档与备份字节均被破坏时调用加载
- **THEN** 结果状态为 `Corrupted`，携带错误描述，不抛异常

#### Scenario: 加载不改写磁盘

- **WHEN** 执行任意加载（含回退路径）前后对比存储目录文件内容与修改时间
- **THEN** 所有文件保持不变

### Requirement: 三轨序列化支持

模块 SHALL 提供三种可互换的序列化器：默认序列化器零第三方依赖，往返支持公开字段、`List<T>` 与 Unity 值类型（如 `Vector3`）；Odin 序列化器在 `ODIN_INSPECTOR` 可用时往返支持 `Dictionary<K,V>` 与多态对象；Newtonsoft 序列化器在工程安装 `com.unity.nuget.newtonsoft-json` 时可用。可选序列化器缺席 MUST NOT 影响核心模块编译与默认序列化的运行（编译期整体剔除）。

#### Scenario: 默认序列化器往返

- **WHEN** 未安装任何可选依赖，保存含 `List<int>` 与 `Vector3` 公开字段的数据对象后加载
- **THEN** 往返一致，全程零第三方依赖

#### Scenario: Odin 序列化器往返字典与多态

- **WHEN** `ODIN_INSPECTOR` 可用且注册 Odin 序列化器后，保存含 `Dictionary<string,int>` 与派生类字段的数据对象后加载
- **THEN** 往返一致，派生类型信息保留

#### Scenario: 可选依赖缺席不影响基线

- **WHEN** 工程未安装 Newtonsoft 包且未安装 Odin
- **THEN** 核心模块编译通过、默认序列化保存加载正常，可选序列化器代码不参与编译

### Requirement: 序列化器标识与按档还原

每份存档 MUST 记录其使用的序列化器标识；加载 MUST 按存档记录的标识选择序列化器还原，而非按当前默认序列化器。不同键 SHALL 允许使用不同序列化器。存档记录的序列化器未注册时，加载 MUST 返回明确的失败状态与错误描述，不得静默用其他序列化器错读。

#### Scenario: 非默认序列化器保存后按标识还原

- **WHEN** 以序列化器 A 保存某键，随后将默认序列化器切换为 B，再加载该键
- **THEN** 仍按 A 还原成功

#### Scenario: 序列化器未注册

- **WHEN** 存档记录的序列化器标识在当前注册表中不存在时加载
- **THEN** 返回失败状态，错误描述指明缺失的序列化器标识

### Requirement: 保存管理扩展点

模块 SHALL 以三个相互隔离的接口暴露扩展点：序列化（对象↔字节）、存储（字节持久化，契约含提交式写入与备份读取）、保存管理（保存 / 加载编排）。用户 MUST 能经门面注册自定义序列化器、替换存储实现、以及替换保存管理器整体接入自定义保存管理方案；替换后 subsequent 保存与加载 MUST 走新实现，且默认实现不被修改（对扩展开放、对修改关闭）。

#### Scenario: 自定义保存管理器接管

- **WHEN** 用户实现保存管理接口并经 `SetManager` 替换后执行保存与加载
- **THEN** 调用进入用户实现，默认事务式管理器不再参与

#### Scenario: 自定义序列化器注册往返

- **WHEN** 用户注册自实现的序列化器并以该序列化器保存后加载
- **THEN** 往返经用户实现完成，数据一致

#### Scenario: 替换存储实现

- **WHEN** 用户经 `SetStorage` 替换为内存存储实现后保存并加载
- **THEN** 数据经新存储往返一致，文件系统不产生存档文件

### Requirement: 可选字节变换链（压缩与加密）

模块 SHALL 支持按注册顺序对存档字节施加变换（内置 GZip 压缩与 AES 加密实现），默认不启用任何变换；变换标识 MUST 记入存档，加载时按记录逆序还原。启用加密后，以错误密钥加载 MUST 判定失败而非返回错误数据。加密密钥 MUST 由游戏侧代码注入，不得持久化到配置资产或存档文件中。

#### Scenario: 压缩往返

- **WHEN** 注册 GZip 变换后保存并加载
- **THEN** 往返一致，存档字节为压缩形态

#### Scenario: 加密往返与错误密钥

- **WHEN** 以密钥 K 启用 AES 变换保存后，分别以密钥 K 与错误密钥 K' 加载
- **THEN** K 加载成功且数据一致；K' 加载返回失败状态，不返回错误数据

#### Scenario: 默认无变换

- **WHEN** 未注册任何变换时保存
- **THEN** 存档 payload 为序列化器原始输出（未经压缩或加密）

### Requirement: 数据版本与迁移

保存 SHALL 携带调用方声明的数据版本号；加载时存档版本与调用方声明的当前版本不一致时：注册了迁移器 MUST 调用迁移器将旧数据升级到当前版本后返回成功；未注册迁移器 MUST 返回 `VersionMismatch` 状态与版本信息，不得静默按当前类型错读。迁移后的数据 MUST NOT 在加载路径自动写回磁盘（下次保存时自然落盘）。

#### Scenario: 迁移器升级旧档

- **WHEN** 存档版本为 1、当前版本为 2 且注册了迁移器时加载
- **THEN** 迁移器被调用，返回升级后的数据，状态为成功

#### Scenario: 无迁移器的版本不匹配

- **WHEN** 存档版本与当前版本不一致且未注册迁移器时加载
- **THEN** 返回 `VersionMismatch` 状态，携带存档版本与当前版本信息

### Requirement: 自动保存与生命周期钩子

模块 SHALL 提供自动保存：注册保存回调与间隔后周期性触发（计时不受 `Time.timeScale` 影响）；应用切后台（`OnApplicationPause(true)`）与退出（`OnApplicationQuit`）时 SHALL 各触发一次保存回调，两者可经配置独立关闭。自动保存 MUST 可清除；清除后不再触发。

#### Scenario: 周期触发

- **WHEN** 注册间隔为 N 秒的自动保存并运行超过 N 秒（Play 模式）
- **THEN** 保存回调至少被触发一次

#### Scenario: 切后台与退出触发

- **WHEN** 自动保存已注册且对应开关开启，模拟 `OnApplicationPause(true)` 或 `OnApplicationQuit`
- **THEN** 保存回调被触发一次

#### Scenario: 清除后不触发

- **WHEN** 清除自动保存后经过原间隔时长并模拟切后台
- **THEN** 回调不再被触发

### Requirement: 配置资产与内存兜底

模块 SHALL 提供 `SaveConfigSO` 配置资产（存储目录、默认序列化器标识、备份开关、切后台 / 退出保存开关），经既有 `Tools/Aesir/Modules/Create Module Config Assets` 菜单显式幂等创建；包导入时 MUST NOT 自动写入用户工程。未指定配置资产时模块 MUST 以代码默认值正常运行（内存兜底，不落盘配置）。

#### Scenario: 无配置资产正常运行

- **WHEN** 工程中不存在 `SaveConfigSO` 资产时执行保存与加载
- **THEN** 以代码默认值正常往返，不创建任何配置资产文件

#### Scenario: 菜单幂等创建

- **WHEN** 连续两次执行 Create Module Config Assets 菜单
- **THEN** 配置资产只创建一份，第二次跳过且不报错

### Requirement: 模块生命周期惯例

模块 MUST 遵循 RAM 模块单例惯例：优先识别场景中预放置的实例（含未激活对象），未找到时懒创建并挂到 `AesirModules` 宿主下；DontDestroyOnLoad 由序列化字段控制；静态状态 MUST 在 `SubsystemRegistration` 重置以兼容跳过域重载的 Enter Play Mode 设置。

#### Scenario: 预放置实例优先

- **WHEN** 场景中预放置了模块实例（含未激活）时首次访问门面
- **THEN** 使用预放置实例，不重复创建

#### Scenario: 连续两次 Play 无静态残留

- **WHEN** 启用跳过域重载的 Enter Play Mode 设置并连续进入两次 Play
- **THEN** 第二次 Play 的模块状态从零开始，不残留上一轮的存档注册表或自动保存计时
