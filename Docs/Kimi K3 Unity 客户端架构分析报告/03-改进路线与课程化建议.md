# 03 · 改进路线与课程化建议

> 目标：把 ACA 从"设计正确的框架"打磨到"可以开课的状态"。
> 所有事项按优先级排列：**P0 = 开课前必须完成；P1 = 开课前应该完成；P2 = 加分项，可随课程迭代。**

---

## 一、P0 · 开课前必须完成（3 项）

### P0-1 统一两个示例的写入口径

**问题**：框架承诺"状态仅通过 Command 写入"，Counter-MVC 遵守，Counter-MVP 绕过（Presenter 直接调 `Model.Increase()` 并手动推送刷新）。

**建议修法**：MVP 示例保留 MVP 的经典结构（Passive View + Presenter 推送），但**写入路径改为走 Command**：

```
修改前：View事件 → Presenter → Model.Increase()（直写）→ 手动 _view.UpdateCount()
修改后：View事件 → Presenter → ExecuteCommand<XxxCommand>() → Model → Presenter 读回 → _view.UpdateCount()
```

这样两条示例共享**同一条写入铁律**（"所有写入必须经过 Command"），差异只在**刷新路径**（MVC 用 ObservableValue 订阅 / MVP 用 Presenter 推送）——而这个差异恰好就是 MVC 与 MVP 的本质区别，值得在课程里正面讲解，而不是像现在这样混在"到底能不能直写 Model"的困惑里。

**验收标准**：学生在任意示例中搜索 Model 的写方法调用点，结果一定只出现在 Command 类里。

### P0-2 对齐 README 快速开始与真实示例

**问题**：README 用 `AesirView` + 构造注入 Controller；实际示例用 `MonoView` + 无参构造。两张皮。

**建议**：以**真实示例为准**改 README（示例经受了编译和运行检验，README 没有）。同时全文统一：教学主线只用 `MonoView` / `MonoViewController` 系列，`Aesir*` 系列降级为"Odin 增强版"一句话。

**验收标准**：把 README 快速开始的代码原样贴进新工程，一次编译通过、一次运行成功。

### P0-3 显式文档化"最小可用路径"

**问题**：完整 MVC 计数器约 8 个文件，对初学者是第一眼冲击。框架其实已有更短路径（`MonoViewController<T>` 双角色，约 5 个文件），但没有作为"第一步"呈现。

**建议**：在 README 快速开始之前插入"两步走路径图"：

```
第一课（跑通闭环，5 文件）：
  Context + IModel/Model + Command + MonoViewController（面板兼 Controller）

第二课（拆出完整分层，8 文件）：
  把 MonoViewController 拆成 MonoView + 独立 Controller，理解为什么拆
```

这恰好是天然的课程结构：**先让学生用最少概念体验到"数据驱动 UI"的爽感，再拆层讲为什么**。渐进式从"框架能力"变成"教学节奏"。

**验收标准**：一个从未见过框架的学生，照文档 30 分钟内从空场景跑到计数器可点击。

## 二、P1 · 开课前应该完成（4 项）

### P1-1 写入约定显式化（应对"View 其实能直写 Model"）

结构化解法（读/写双接口）会显著增加接口数量，**不建议**在初学者框架的当前阶段引入。建议采用约定式解法，三件套：

1. 在 README 设计边界表加一行："View 中禁止调用 Model 的写方法（编译器不拦，属于约定），写入必须经 Command"；
2. 课程中用一节课正面演示"直写也能跑，但项目变大后会发生什么"——**让学生怕一次，比堵死更有效**；
3. （可选，低成本）写一个示例展示进阶读/写双接口模式，标注"进阶，可跳过"。

### P1-2 发布《事件机制决策表》

按 02 文档盲区 2 的表格，写进官方文档并作为课程教具。**核心原则：每个场景有且只有一个默认答案。**

### P1-3 发布《常见陷阱清单》

至少收录（每条配错误现象 + 异常截图 + 一句话修法）：

- 按实现类注册、按接口获取（Register/Get 类型参数不一致）
- `Configure()` 或模块 `OnInitialize()` 中访问 `Interface`（递归创建第二实例）
- 注册顺序错误 / 模块循环依赖（框架会抛，但学生需要知道怎么读这个异常）
- 监听回调里抛异常（fail-fast 语义）
- 忘了 `RemoveListenerWhenGameObjectOnDestroyed`（什么时候可以省，什么时候不能省）

同时可把 `GenericLocator` 的"未注册"异常消息增强为**近失识别**：当查询类型未命中、但已注册键中存在可赋值给查询类型的键时，在异常消息里提示"你是否想获取 XxxImpl？Register 与 Get 必须使用相同类型参数"。一行反射，体验收益大。

### P1-4 API 冻结评审

课程视频的维护成本极高：**课程发布后每一次 breaking change，都是对所有已购学生的负债**。开课前做一次逐 API 评审，重点确认这些"以后想改就晚了"的名字：

- 核心类型名：`AbstractContext` / `Interface` / `ICanXxx` / `MiniEvent` / `ObservableValue`
- 核心方法名：`Configure` / `RegisterModel` / `GetModel` / `ExecuteCommand` / `AddListenerAndInvoke`
- 基类选择：`MonoView` 与 `AesirView` 的双轨制是否长期维持

评审输出一份《1.0 API 冻结清单》，课程只讲清单内的 API。

## 三、P2 · 加分项（随课程迭代）

| 项 | 价值 | 说明 |
|----|------|------|
| **脚手架菜单** | 高 | `Create → Aesir → Model/Command/Context` 模板生成，消除"8 个文件"的恐惧感；与路线图 Editor 工具链吻合 |
| **运行时调试窗口** | 高 | 显示当前 Context 注册的 Model/Service 列表 + 各 ObservableValue 实时值。**"让学生看见架构"是教学放大器** |
| **更多示例** | 中 | 建议顺序：存档（Service 主场）→ 敌人血条（ObservableValue 主场）→ 背包（综合）→ 场景切换 |
| **Roslyn Analyzer** | 低 | 把"View 禁写 Model"从约定变警告；远期项，不阻塞 |

## 四、课程大纲建议（10 课）

> 设计原则：**每课一个可运行产物；前 3 课让学生获得正反馈，第 4 课起引入规则；进阶内容全部后置。**

| 课 | 主题 | 产物 | 对应理念 |
|----|------|------|---------|
| 1 | 为什么需要架构：解剖一个 MonoBehaviour 面条项目 | 看懂"关系失控"的代价 | (a) |
| 2 | 30 分钟跑通计数器（最小路径，5 文件） | 可点击的计数器 | 简单>灵活 |
| 3 | Model 与 ObservableValue：数据驱动 UI | 血条 / 金币显示 | 单向数据流 |
| 4 | Command：所有写入只有一个入口 | 给计数器加"步长"功能 | (c) |
| 5 | 拆出 Controller：从 5 文件到 8 文件，为什么 | 完整 MVC 计数器 | 角色分层 |
| 6 | Service：跨模块协调（做一个存档服务） | 存档读档 | MVC-S |
| 7 | 事件三兄弟与自动注销：内存泄漏专题 | 决策表 + 无泄漏订阅 | (b) |
| 8 | MVP 变体：什么时候该让 View 变"笨" | MVP 计数器 | 角色分层 |
| 9 | 生命周期与单例：不消灭单例，消灭失控 | 讲清两阶段初始化 | (b) + 单例观 |
| 10 | 综合实战 + 给游戏逻辑写单元测试 | 完整小游戏 | 全部 |

第 10 课的"纯 C# Model 可单元测试"是 ACA 相对纯 MonoBehaviour 教学的**差异化卖点**，建议作为课程宣传点之一。

## 六、结语

ACA 目前的状态可以概括为：**骨架正确、肌理扎实、气血还差最后一点通畅**——差的那一点不在架构设计，而在"示例、文档、理念三者的执行一致性"。P0 三项都是几天内可完成的工作，完成后 ACA 就具备了作为"Unity 中文初学者第一个框架"开课的全部条件。

这套框架最独特的价值，是它本身就示范了它要教的东西：**克制、边界、契约**。课程讲 ACA，其实就是 ACA 在讲它自己——这是它能成为一门好课的根本原因。
