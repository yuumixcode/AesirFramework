## 一、做了什么

重新设计了框架 MonoBehaviour 单例**"预放置实例 / 自动生成实例 → DontDestroyOnLoad（DDOL）场景"** 的控制机制：由"按实例来源隐式决定"改为"由每个实例上的布尔序列化字段显式决定"。

### 旧机制（0.7.0 起）

- 场景预放置实例：**不**进入 DDOL 场景，随所在场景卸载销毁（为多场景叠加加载设计）；
- 运行时自动创建实例：进入 DDOL 场景（由 `static bool _pendingDontDestroyOnLoad` 一次性静态标志在 Instance getter 与 Awake 之间传递决策）。

问题：预放置实例的"不 DDOL"是隐式默认，用户无感知、无显式入口；静态标志引入了置位/消费/复位的时序维护成本（含 Domain Reload 下的复位处理）。

### 新机制

四个直接参与 DDOL 决策的脚本新增序列化字段：

```csharp
[SerializeField]
[Tooltip("勾选：本物体加入 DontDestroyOnLoad 场景，跨场景持久存在（默认）。\n...")]
bool dontDestroyOnLoad = true;
```

| 脚本 | 包 | 字段生效范围 |
|---|---|---|
| `AesirArchitecture` | Architecture | 预放置与运行时创建均生效 |
| `AesirModules` | Modules | 预放置与运行时创建均生效 |
| `UIRoot` | Modules（UI 模块） | 预放置与运行时创建均生效 |
| `UIModule` | Modules（UI 模块） | **仅预放置为根物体时生效**；运行时自动创建时挂载于 [Aesir Modules] 宿主下，跟随宿主决策 |

### 行为矩阵

| 实例来源 | dontDestroyOnLoad | 行为 | 旧机制对照 |
|---|---|---|---|
| 场景预放置 | ✅ true（默认） | Awake 时加入 DDOL 场景，跨场景持久 | **变化**：旧机制保留在场景中 |
| 场景预放置 | ❌ false | 保留在所在场景、随场景卸载销毁 + 三重提醒 | 行为同旧机制，但需显式选择 |
| 运行时创建 | ✅ true（恒为默认） | 加入 DDOL 场景 | 不变 |
| 运行时创建（子模块） | —（跟随宿主） | 跟随宿主 GameObject 的 DDOL 决策 | 不变 |

### "不加入 DDOL"的三重提醒

取消勾选 `dontDestroyOnLoad` 时，用户会从三个渠道获知"必须自行处理多场景叠加（Additive）加载"：

1. **字段 Tooltip**（`UnityEngine.Tooltip`，原生/Odin Inspector 通用）——悬停即说明两个字段的后果；
2. **Odin InfoBox 警告**（AttributeProcessor 注入，字段为 false 时显示）——Runtime 程序集保持零 Odin 依赖；
3. **运行时 LogWarning**（Awake 时输出一次，`[Conditional("UNITY_EDITOR")]` 仅编辑器期，不污染构建日志）。

### 同步删除的旧机制

- `static bool _pendingDontDestroyOnLoad`（AesirArchitecture / AesirModules / UIRoot）——字段默认值天然覆盖运行时创建路径（`AddComponent` 同步触发 Awake，实例字段初始化为 true），静态标志及其在 Instance getter 中的置位/复位时序全部消失；
- `bool _isPrePlaced` 与 `IsPrePlacedFieldName`（AesirArchitecture）——Inspector 警告的显示条件从"是否预放置"（运行时才可知）改绑"字段是否关闭"（序列化即可见），编辑期就能暴露风险。

## 三、修改思路

### 1. 用"实例序列化字段"统一两种实例来源的决策路径

旧机制按"实例从哪来"（预放置 vs 运行时创建）做隐式分流，需要静态标志跨方法传递决策。新机制把决策落到**每个实例自己的序列化字段**上：

- 运行时创建路径**天然复用默认值 true**——`AddComponent` 同步触发 Awake，实例字段初始化器先行执行，无需任何传递机制；
- 预放置路径在 Inspector 中显式可见、可改；
- 静态标志 `_pendingDontDestroyOnLoad` 的置位/消费/复位时序（含 Domain Reload 复位、编辑模式下访问 Instance 导致标志悬挂的边界情况）整体消失，符合项目极简原则。

### 2. "默认加入 DDOL"与"关闭时提醒"的责任划分

按任务要求，默认勾选（跨场景持久，多数项目的安全默认）；取消勾选是有意识的进阶选择（多场景叠加加载工作流），因此框架的义务是**充分告知风险而非替用户兜底**：

- 提醒走"编辑期提示"（Tooltip + InfoBox）优先，运行时日志仅编辑器期生效（`[Conditional("UNITY_EDITOR")]`）——与项目"低概率问题用文档约定或编辑期提示替代运行时防御"的铁律一致；
- 警告显示条件绑定序列化字段值而非运行时状态（旧的 `_isPrePlaced` 只在 Play 模式 Awake 后才为 true，编辑期 InfoBox 永远不可见），编辑期即可暴露风险。

### 3. UIModule 的特殊处理：根物体守卫

Unity 限制 `DontDestroyOnLoad` 仅对根 GameObject 有效。UIModule 运行时自动创建时挂载在 [Aesir Modules] 宿主下（非根物体），若不加守卫直接按字段调用 DDOL 会触发 Unity 报错。设计取舍：

- 预放置为根物体 → 字段生效，自持 DDOL 决策；
- 运行时自动创建（非根）→ 跳过 DDOL、跟随宿主（宿主的开关已对整棵子树发过提醒，子模块不再重复告警）；
- `transform.root == transform` 守卫同时天然防御了"用户把 UIModule 预放置在其他物体下"的边缘情况。

### 4. 宿主—子模块的决策层级

整个框架的持久化决策收敛为三个"宿主"节点：[Aesir Architecture]、[Aesir Modules]、[UIRoot]。挂在宿主上/宿主下的组件（MonoLifecycleProxy、RemoveListenerOnSceneUnloadedTrigger、UIModule、SceneModule、EventModule）不重复携带字段——宿主的开关即控制整棵子树，避免同物体上多个开关互相矛盾的配置空间。

## 五、迁移影响

- **Breaking**：预放置实例默认行为从"保留在所在场景"变为"进入 DDOL 场景"。依赖旧行为的多场景叠加工作流需在每个预放置实例上**显式取消勾选** dontDestroyOnLoad（Inspector 警告会持续提醒后果）；
- 两个包的 `CHANGELOG.md` 均已在 `[Unreleased]` 段记录（Architecture 记为 Breaking Changes，Modules 记入 Changed）；版本号发布流程交由 `aesir-version-sync` 技能统一处理，本次未改动 package.json。
